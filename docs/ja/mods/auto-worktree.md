# auto-worktree

[English](../../mods/auto-worktree.md) | 日本語

セッションの最初のプロンプトを送った時点で、git のワークツリーを作ってそこへ移ります。やることを決めてからセッションを始める使い方なら、最初のプロンプトがそのまま「このワークツリーで何をするか」になり、メインのチェックアウトには手を触れずに作業が進みます。複数のセッションを並べて動かしても、互いの作業ファイルがぶつかりません。

Claude Code にはワークツリーを作る仕組み（`claude --worktree`、EnterWorktree）がありますが、拡張機能にはセッションを始めるたびに自動で作る設定がありません。auto-worktree はその隙間を埋めます。

## 最初のプロンプトで起きること

1. プロンプトを送ると、Claude に渡す前に、Claude が EnterWorktree を呼ぶのと同じ呼び出しをします。`.claude/worktrees/<ランダムな名前>` にワークツリーができ、ブランチ `worktree-<名前>` で作業が始まります
2. 移ったことをトーストで知らせ、最初のプロンプトに添えて Claude にも伝えます。拡張機能ではトーストが出ないので、Claude が最初の返答の冒頭で伝えます
3. 作ったワークツリーがメインのチェックアウトの `git status` に出ないよう、そのクローンの `.git/info/exclude` に `/.claude/worktrees/` を 1 行足します。このファイルは commit されません

どこから枝分かれするか、`.env` などをコピーするかは、Claude Code の設定（`worktree.baseRef`、`.worktreeinclude`、`worktree.symlinkDirectories`）に従います。auto-worktree は独自の設定を持ちません。

EnterWorktree の許可を求められたときに拒んだ場合や、作れなかった場合は、理由をトーストで出し、プロンプトは元の場所でそのまま送ります。

## ワークツリーに入らないとき

次のどれかに当てはまると、何もしません。

- 2 通目以降のプロンプト。再開したセッションも、すでにプロンプトを送っているので入らない
- 人のいないセッション（`claude -p` など）
- git のリポジトリの外
- すでにワークツリーの中にいる

拡張機能のセッションは、mod から見ると `claude -p` と同じく画面がありません。そこで、環境変数 `CLAUDE_CODE_ENTRYPOINT` が `claude-vscode` なら、人が使っているセッションとみなします。

いまのセッションが入る条件を満たしているかは、`/auto-worktree` で確かめられます。

```text
次のプロンプトでワークツリーに入ります。
ディレクトリ: /Users/me/repo
リポジトリ: /Users/me/repo
画面: なし
起動元: claude-vscode
これまでのプロンプト: 0 通
```

## rtk を入れていても git が使える

ワークツリーに入ったセッションでは、Claude Code は、どのディレクトリを対象にするか読み取れない git を拒否します。[rtk](https://github.com/rtk-ai/rtk) のフックは `git status` を `rtk git status` に書き換えるため、そのままでは git がすべて拒否されます。

auto-worktree は、ワークツリーの中で Claude が Bash を実行するとき、コマンドの位置にある `git` を、rtk のフックより先に `\git` に変えます。

- シェルにとって `\git` は `git` と同じです。Claude Code の権限ルール（`Bash(git push:*)` など）も、そのまま `\git` に当たります
- rtk はこの形を書き換えないので、隔離のチェックを通ります
- 変えるのはコマンドの位置にある `git` だけです。引用符の中、引数としての `git`、ヒアドキュメントの中身、コメントは変えません

代わりに、ワークツリーの中の git だけは rtk による出力の圧縮が効かなくなります。また、`\git` はシェルのエイリアスを通らないので、`git` をエイリアスにしている場合はその設定が使われません。

rtk のフックそのものを直さないのは、rtk がフックのハッシュを照合しており、手を入れると rtk のすべての書き換えが止まるためです。

## コマンド

| コマンド | 動き |
| --- | --- |
| `/auto-worktree` | このセッションが次のプロンプトでワークツリーに入るかと、その理由を出す |

## 使い終わったワークツリーの片づけ

auto-worktree はワークツリーを消しません。作業が終わったら、セッションの中で ExitWorktree を使うか、ターミナルで `git worktree remove .claude/worktrees/<名前>` を実行して片づけます。ブランチ `worktree-<名前>` も残るので、要らなければ `git branch -d` で消します。

エディタのウィンドウは元のフォルダを開いたままです。ワークツリーのファイルは、そのフォルダの中の `.claude/worktrees/<名前>/` から開けます。
