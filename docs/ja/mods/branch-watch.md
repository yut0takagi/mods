# branch-watch

[English](../../mods/branch-watch.md) | 日本語

同じ worktree で Claude Code のセッションを 2 つ以上動かしていると、片方が `git checkout` したことにもう片方は気づきません。気づかないまま commit すると、そのコミットは意図しないブランチに入ります。branch-watch は、セッションごとに「本来のブランチ」を覚えておき、ずれていれば知らせ、そのまま commit しようとしたら止めます。あわせて、どのセッションがどの worktree のどのブランチにいるかを一覧にします。

## ずれを見つける仕組み

branch-watch は worktree ごとに「基準」を持ちます。基準は、そのセッションが初めてその worktree で作業したときのブランチです。

ずれを確かめるのは、ツールを呼ぶたびと、15 秒ごとです。15 秒ごとに見るのは、Claude が待機しているあいだに別のセッションが切り替えた場合も拾うためです。基準と今のブランチが違えば、トーストで一度だけ知らせ、ステータス行に `⚠` を付けます。

どの worktree で作業しているかは、次の順に決めます。

1. 最後に Edit・Write で編集したファイルがある worktree
2. 最後に実行したコマンドの対象。`git -C <dir>` と、先頭の `cd <dir> &&` を読む
3. どちらもなければ、セッションのディレクトリ

git の外（`~/.claude` のメモなど）を編集しても、作業している worktree は変わりません。

## commit を止める条件

基準と違うブランチで `git commit` を含むコマンドが実行されそうになると、止めます。止めた理由は Claude に伝わるので、Claude は人に判断を仰ぎます。

ただし、このセッション自身が `git checkout`・`git switch`・`gh pr checkout` を実行した場合は、意図した切り替えなので、切り替え先を新しい基準にします。止めるのは、ほかのセッションが切り替えた場合だけです。

止められたときの選択肢は 2 つです。

- 元に戻す: `git checkout <基準のブランチ>`
- 今のブランチで続ける: 入力欄で `/branch-watch accept`。Claude やほかのプラグインからの実行は受け付けません

## ステータス行の読み方

| 表示 | 意味 |
| --- | --- |
| `⎇ repo / feature/a` | worktree `repo` のブランチ `feature/a` で作業していて、基準どおり |
| `⚠ ⎇ repo / feature/b（このセッションは feature/a）` | 基準は `feature/a` だが、今は `feature/b` になっている |
| `… 👥 +1` | 同じ worktree で、ほかにも 1 つのセッションが動いている |

detached HEAD のときは、ブランチ名の代わりに `HEAD` と出ます。まだコミットのないリポジトリでも、ブランチ名を出します。

## コマンド

| コマンド | 動き |
| --- | --- |
| `/branch-watch` | 動いているセッションを worktree ごとにまとめたペインを開き、このセッションの基準と今のブランチを返す。ペインを開けないときは、一覧を返答に出す |
| `/branch-watch accept` | 今のブランチを基準にする。人が入力したときだけ受け付ける |

ペインには、セッションごとに作業中か待機中か、最初のプロンプトの書き出し（32 文字まで）、session id の先頭 8 文字を出します。基準と違うブランチにいるセッションには基準を添え、同じ worktree に 2 つ以上のセッションがいれば `⚠` を付けます。

## 書き込むファイル

一覧を作るため、各セッションは自分の様子を `~/.claude/branch-watch/sessions/<session id>.json` に 15 秒ごとに書きます。`CLAUDE_CONFIG_DIR` を設定していれば、その下に書きます。

- 60 秒書かれていないセッションは、止まったとみなして一覧から外します
- 10 分を過ぎたファイルは消します
- セッションが終わるときは、自分のファイルを消します

中身は、session id、worktree のパス、ブランチ、基準、最初のプロンプトの書き出し、作業中かどうか、書いた時刻です。ネットワークには何も送りません。

## 拡張機能で使うとき

ステータス行とトーストが出ないため、`/branch-watch` の返答で状況を確かめます。ずれが起きたときは、次のプロンプトかツールの結果に一言添えて Claude に伝え、Claude が返答で人に知らせます。同じずれを伝えるのは 1 回だけで、サブエージェントには伝えません。

## 制限

- commit かどうかは、コマンドの文字列で判断します。エイリアスやスクリプトを経由した commit は見分けられません
- コマンドの対象ディレクトリは `git -C <dir>` と先頭の `cd <dir> &&` からしか読みません。それ以外はセッションの今のディレクトリとみなします
- 一覧に出るのは、branch-watch を入れたセッションだけです
- `git -C <dir> log` のような読み取りだけのコマンドでも、作業している worktree はそこに移ります
