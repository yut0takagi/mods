# push-gate

[English](../../mods/push-gate.md) | 日本語

`git push` や `gh pr merge` のように、人の確認なしに実行させたくないコマンドを止めます。人が承認したときだけ、そのコマンドを 1 回通します。承認はボタンか、人が入力欄から打ったコマンドでしか受け付けないので、Claude が自分で承認することはできません。

Claude Code の権限設定（`permissions.ask`）でも確認は出せます。ただ、確認を省くモード（`--dangerously-skip-permissions` など）で動かすと、その確認は出ません。push-gate は権限の確認より前にツールの呼び出しを止める作りなので、このモードでも止まる想定です（このモードでは試していません）。

## 承認の流れ

1. Claude が対象のコマンドを実行しようとすると、push-gate が止めます。Claude には「人に承認を頼んで、このターンを終える」よう伝えます
2. 入力欄の上の帯に、止めたコマンドと「承認」「却下」のボタンが出ます
3. 「承認」を押すと、push-gate が同じコマンドをもう一度実行するよう Claude に頼むプロンプトを送ります。そのコマンドは 1 回だけ通ります
4. 「却下」を押すと、そのコマンドを実行しないよう Claude に伝えるプロンプトを送ります

承認が効くのは、止めたときとまったく同じ文字列のコマンドだけです。Claude が `--force` を足すなどして中身を変えたら、改めて承認が要ります。使われなかった承認は 10 分で切れます。

## コマンド

| コマンド | 動き |
| --- | --- |
| `/push-gate` | 承認を待っているコマンドを表示する |
| `/push-gate approve` | 承認する。人が入力したときだけ受け付ける |
| `/push-gate reject` | 却下する。人が入力したときだけ受け付ける |

帯が表示されない環境（拡張機能など）では、`/push-gate approve` と `/push-gate reject` を使います。チャットに「承認します」と書いても承認にはなりません。

## 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| `commands` | `git push, gh pr merge` | 承認が要るコマンド。カンマで区切る |

各項目は語の並びで照合します。`git push` なら、`git` のあとに `push` が来るコマンドを止めます。間にオプションが挟まっても止めるので、`git -C ../repo push` も対象です。

ほかのコマンドを足す例です。

```text
git push, gh pr merge, gh release create, npm publish
```

## 制限

- コマンドの文字列で判断するため、エイリアスやスクリプトを経由した push は見分けられません
- 文字列のどこかに対象の語の並びがあれば止めます。commit メッセージやヒアドキュメントの中に「git push」と書いただけでも止まります（既知の問題。回避のしかたは [困ったとき](../troubleshooting.md#push-gate-に止められたがpush-はしていない)）
- 承認待ちのコマンドは 1 つだけ覚えます。別のコマンドが止められると、前の承認待ちは置き換わります
