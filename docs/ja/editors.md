# VS Code・Cursor の拡張機能で使うとき

[English](../editors.md) | 日本語

拡張機能では、mod が画面に出すもの（ステータス行、トースト、ペイン、帯、ボタン）が表示されません。そのため、この環境の各 mod は、内容をコマンドの返答か Claude の返答で伝える作りにしています。Claude Code 2.1.289 の VS Code 拡張機能と、Cursor で確かめました。

## 拡張機能で届くもの・届かないもの

| 届く | 届かない |
| --- | --- |
| 音（done-chime） | ステータス行 |
| スラッシュコマンドの返答 | トースト |
| mod が Claude に添えた文（Claude が返答の中で伝える） | ペインと帯 |
| ツール呼び出しを止めること（push-gate、branch-watch） | ボタン |

拡張機能のセッションは、mod から見ると画面のないセッションです。`claude -p` で動かしたときと同じ形になるため、auto-worktree は環境変数 `CLAUDE_CODE_ENTRYPOINT` が `claude-vscode` かどうかで、人が使っているセッションだと判断しています。

## mod ごとの使い方

| mod | 拡張機能での使い方 |
| --- | --- |
| auto-worktree | ワークツリーに移ったことを、Claude が最初の返答の冒頭で伝える |
| branch-watch | `/branch-watch` の返答に、基準と今のブランチ、セッションの一覧が出る。ブランチのずれは Claude が返答で伝える（同じずれは 1 回だけ） |
| push-gate | 承認ボタンは出ない。入力欄で `/push-gate approve` と打って承認し、取りやめるなら `/push-gate reject` と打つ |
| session-diff | `/session-diff` で編集したファイルの一覧が、`/session-diff <パス>` でそのファイルの差分が返答に出る |
| pr-pane | `/prs` で PR と CI の状態が返答に出る。画面がないあいだは、定期的な取り直しを止める |
| side-question | `/btw <質問>` が答えを待って、返答に出す |
| usage-meter | `/usage-meter` で、直近のターンの数と、直近 40 ターンの推移が返答に出る |
| done-chime | 音だけで知らせる（macOS） |
| ja-check | トーストが出ないので、既定の `toast` では何も起きないように見える。拡張機能では `mode` を `rewrite` にすると、日本語での書き直しが頼まれる |

## 返答に出したものは会話に残る

スラッシュコマンドの返答は Claude も読むため、返答に出した内容は会話の一部になり、以降のターンで Claude の文脈に入ります。side-question はターミナルでは答えを会話に残しませんが、拡張機能では残ります。差分や PR の一覧も同じで、大きな差分を何度も出すと、そのぶん文脈を使います。

## push-gate の承認は、入力欄から打ったものだけが通る

チャットで「承認します」「push して」と書いても、push-gate は承認とみなしません。入力欄から `/push-gate approve` と打つ必要があります。Claude 自身が承認できないようにするための制限です。承認すると、push-gate が同じコマンドを実行するよう Claude に頼むメッセージを送り、そのコマンドが 1 回だけ通ります。

## 確かめていないこと

人にだけ見せて Claude には読ませない表示（`$.ui.log`、`session.append` の system 行）は、拡張機能では描かれないと見ています。拡張機能のコードを読んだ結果で、実機では確かめていません。拡張機能の今後の版で、mod の画面が描かれるようになる可能性もあります。
